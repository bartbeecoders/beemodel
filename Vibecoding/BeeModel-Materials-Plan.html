Phase 12 · v0.13.0 · PBR materials & material editor

Materials you build like in Unreal

BeeModel already renders a principled (PBR) material and has a small shader graph: 12 nodes of 9 types, one output per node and 5 material sockets. This phase turns it into a full node-based material editor modelled on Unreal Engine's. It brings larger graphs, about 60 node types with several outputs each, a Material Output node with every PBR input, live node previews and a preview viewport, parameters and material instances, material functions, PBR texture sets, glTF textures and shader graphs on the GPU. Everything stays hand-written x86-64, with no libraries.

BeeModel · Vibecoding/BeeModel-Materials-Plan.html · Companion to the Masterplan, "Nodes & procedural" and the UI plan · Written 2026-10-15 against v0.12.0

Goals

Real PBR

The metallic/roughness model end to end, as Unreal and glTF use it: base colour, metallic, specular, roughness, emissive, opacity, normal, ambient occlusion, clear coat, transmission and IOR. Texture sets from Substance, Quixel, Poly Haven or ambientCG drop straight in, with the right colour spaces.

A real node editor

Zoom, box select, copy and paste, reroutes, comments, a searchable palette, live thumbnails on every node, a preview viewport and a details panel. A 40-node material stays readable and responsive.

Same look everywhere

The viewport material preview, the CPU path tracer, the GPU path tracer, baking and glTF export all evaluate the same graph. A material looks the same in each.
Rule kept. Old files, scripts and agent calls keep working. A v0.12 scene opens with its graphs intact, and node(), link(), nodeset() and socket() keep their meaning; they only gain optional arguments.

The material editor

The Shading workspace with a node editor in material mode.

Mouse

  • Wheel: zoom about the pointer (25% to 200%). MMB or Space+LMB on empty canvas: pan. LMB-drag on empty canvas: box select (Shift adds, Ctrl removes).
  • Drag from a pin into empty space: the add menu opens, filtered to nodes with a matching input, and the new node is linked.
  • Double-click a wire: add a reroute. Alt-click a pin: cut its links. Ctrl-drag across wires: cut them.
  • Double-click a value: type a number or an expression (0.5*2, pi/4). Drag a value: change it; Shift for fine, Ctrl for steps.
  • Drag a palette entry or an image from the asset browser onto the canvas: add that node or a Texture Sample.

Keys

  • Shift+A add menu, X/Del delete, Ctrl+C/V/X copy, paste, cut, Ctrl+D duplicate
  • C comment around the selection, H collapse, Ctrl+G make a function, Tab enter or leave a function
  • Home frame all, F frame the selection, Q/W/S/D with Shift: align left, top, middle, distribute
  • Unreal shortcuts held over the canvas while clicking: 1 Constant, 3 Constant3, T Texture Sample, L Lerp, M Multiply, A Add, S Scalar Parameter, U Texture Coordinate

Data model

One material is one record, as it is today. The record only grows.

Material record v2: 4 KiB

  • Bytes 0–127 hold the principled values and stay where they are. New fields go in the spare bytes 96–127: blend mode, flags (two-sided, cast shadow), the opacity-mask clip value, the parent material (for instances) and a graph version.
  • From byte 128 the graph header is unchanged: GR_N at 128, the old 5 sockets at 132 and the output position at 152. The nodes start at 160 as before, and now 48 of them fit (160 + 48 × 72 = 3616).
  • From byte 3616: all 16 Material Output pins (a link each, holding the node + 1 and the output in bits 16–23), the comment frames (8), the live-node mask and the instance overrides.
  • MA_SZ and MA_SHIFT move into const.inc, so no file keeps its own copy. Each hard-coded shl 10 is replaced.

Nodes

  • The node layout stays the same as the geometry trees use: a type, 3 inputs (each a link or a constant xyz), 4 values and a position. The editor keeps one code path for all three graph kinds.
  • A node has up to 5 outputs. Links carry the output index in bits 16–23, as tree links already do. Old links (bits 16–23 = 0) mean output 0, which is the old colour/value pair, so old graphs evaluate the same.
  • Nodes that need more than 3 inputs (Material Output, a function call) take their pins from a side table.
  • Reroutes and collapsed nodes are flags in the type word; comments are frames, not nodes.

Evaluation

  • An edit recompiles the graph into a material program: the live nodes in order (those that reach a pin), constants folded, each output a register. Dead nodes cost nothing.
  • The scalar interpreter (path tracer, baking) and a 4-wide SSE interpreter (preview, node thumbnails, 4 pixels at once) run the same program. The GPU runs it as well (M10).
  • Bump re-runs only the subgraph that feeds the height, not the whole graph three times.

Files, undo and sync

  • A new MGR2 chunk holds the graph part beyond byte 128. Old MGRF chunks (896 bytes each) are still read and upgraded. Unknown chunks are skipped, so the file version stays 1.
  • Undo is unchanged: the block is copy-on-write and reference-counted. Live link, co-editing, version control and .beea assets move to the new size; .beea gets version 2 and still reads version 1.

Each type is one row of a metadata table: script name, title, category, header colour, inputs (name, kind, default), values (name, kind, range, choices) and outputs (name, kind). The editor, the palette, the details panel, BeeScript, MCP node_types and the docs are all generated from that row, so a new node is one row plus its evaluator.

Rendering

Material Output pins

  • Base Colour, Metallic, Specular, Roughness, Emissive (an HDR colour; strength is folded in), Normal (from a Bump, Normal Map or Blend Normals node, or any vector in tangent space), Ambient Occlusion (multiplies indirect light in the preview and baked lighting; the path tracer has its own), Clear Coat, Coat Roughness, Transmission, IOR.
  • Opacity (translucent mode) and Opacity Mask (masked mode, clipped at the clip value). The path tracer passes stochastically through both, for camera and shadow rays. The preview dithers translucency and cuts the mask. Two-sided is a material setting.

Issue list

One GitHub issue and one pull request per item, in this order. Each one ships working and tested.

Stage A · the foundation
M1core

Material records v2: 48 nodes, multi-output links, all PBR pins data render

4 KiB records with MA_SZ in const.inc; every hard-coded site updated. 48 nodes, links with an output index, 16 Material Output pins, the MGR2 chunk with upgrade of MGRF, .beea v2, live link and co-editing. graph_shade returns every pin, and the path tracer and preview honour specular, IOR, transmission, coat, opacity, opacity mask and AO from nodes. Blend mode and two-sided settings. Dead nodes are skipped.

Exit: a v0.12 scene with graphs renders pixel-identical; a 48-node graph saves, reopens and undoes; an opacity-mask leaf casts a cut-out shadow in the path tracer.
M2core

Node catalogue: inputs, math, vector, colour, textures nodes

The metadata table and about 60 types from the catalogue (parameters and functions come later). Texture Sample gets several outputs, a UV input, a sampler type and wrap modes. Each image gets a colour space (sRGB or non-colour, guessed from the name); 8-bit data maps stop being decoded as sRGB.

Exit: each node type has a script test against a reference value; Voronoi and Fresnel shots look right in the preview.
M3core

Material program: compile once, run 4-wide perf

Edits compile the graph into a register program (live nodes only, constants folded, bump subgraph separated). A scalar interpreter and an SSE 4-wide interpreter run it; the preview shades four pixels per call. The self-test compares the two bit for bit on random graphs.

Exit: the 1080p preview of a 40-node material at most 2.5× the cost of a plain principled one; path-tracer samples per second within 10% of v0.12 on the product shot.
Stage B · the editor
M4editor

Canvas: zoom, box select, clipboard, reroutes, comments editor

A zoom about the pointer (text drops to titles below 50%), box select, moving the whole selection, Ctrl+C/V/X/D (also across materials, via the app clipboard), reroutes, comment frames, collapse, align and distribute, wire colours by kind, link cutting, drag from a pin into empty space for a filtered add menu, frame all and frame selected, and a minimap. It works for geometry and logic graphs too.

Exit: fakewl builds a 20-node graph only with the mouse, then copies half of it into a second material.
M5editor

Material Output node, palette, details panel, typed values editor

An Unreal-style main node with all pins (unused ones dimmed). A palette with categories, search and drag-to-add. A details panel in the properties area: the selected node's values as real widgets (sliders, colour pickers, choice lists, image pickers), or the material's settings when nothing is selected. Double-click a value to type it. Unreal's hold-key-and-click shortcuts.

Exit: every node value can be set without the console; the U27 walkthrough is extended with a material built in the editor.
M6editor

Live previews: node thumbnails, preview viewport, stats render

A 48×48 thumbnail on each node, evaluated over a plane by the 4-wide interpreter and cached per graph version. A preview pane in the editor (sphere, cube, plane, cylinder, or the active mesh) that you can orbit, lit with the studio environment. A stats line and warnings (unreachable nodes, a colour plugged into a scalar pin, a missing image).

Exit: editing a value redraws every thumbnail and the preview within one frame for a 24-node graph (≤ 16 ms on 32 threads).
Stage C · reuse
M7reuse

Parameters and material instances workflow

Scalar, Vector and Texture Parameter nodes. material.instance <parent> <name> makes an instance that shares the parent's graph and overrides parameters. In the Material tab each parameter has an override check box, as in Unreal. Changing the parent updates every instance. Parameters can be keyed (material:M:Wear).

Exit: 100 instances of one parent with different colours render in one image; editing the parent changes all of them.
M8reuse

Material functions workflow

Function records with Function Input and Output nodes; a Function Call node with pins generated from them; Ctrl+G makes a function from the selection, Tab enters and leaves. Functions are compiled inline into the program, nest 8 deep, and save as assets.

Exit: a "weathering" function used by three materials; editing it changes all three.
M9reuse

PBR texture sets, sampling quality, presets content

"Import texture set": pick the files, or a folder, in the file browser. Maps are recognised by name (albedo, basecolor, diffuse, col; normal, nor, nrm with the GL or DX convention; roughness, rough; metallic, metal; ao, occlusion; height, disp; emissive; opacity). This builds a full graph with a shared tiling parameter. Textures get mip levels with trilinear filtering. Twenty procedural or principled presets come built in: gold, silver, copper, chrome, brushed aluminium, plastic, rubber, glass, frosted glass, water, ceramic, car paint, wood, marble, concrete, fabric, leather, skin, emissive panel and clay.

Exit: an ambientCG-style folder imports to a correct material in one action; the presets render in a test sheet.
Stage D · everywhere
M10render

Shader graphs on the GPU render

The material program and the scene's textures go to the GPU helper. An interpreter in pt.comp (emitted by spv.s) runs it, so hv_gpu_ok no longer refuses graphs. Programs that use nodes the GPU lacks fall back to the CPU, as HDRI worlds do today.

Exit: tests/gpu.py compares a textured, bumped and masked scene between CPU and GPU (mean difference within the noise).
M11exchange

Baking, glTF and OBJ texture maps exchange

material.bake bakes the base colour, ORM (occlusion, roughness, metallic), normal and emissive pins to images through the mesh UVs. glTF import reads UVs and all five texture slots with KHR_texture_transform; export writes image-only graphs directly and bakes procedural ones. MTL reads and writes map_Kd, map_Ks, map_Ns/map_Pr, map_Pm, map_Ke, map_d and norm/map_Bump.

Exit: the Khronos sample "DamagedHelmet"-style fixture round-trips with textures intact.
M12release

Scripting, agents, docs and release v0.13.0 release

BeeScript: link(m, from, to, input, output), pin names, param(), instance(). MCP: material_graph reads or writes a whole graph as JSON, and node_types covers materials. docs/MATERIALS.md. A walkthrough test, a benchmark, CHANGELOG, README and the tag.

Exit: an agent rebuilds the walkthrough material through MCP with one material_graph call.

Testing

  • Compatibility: v0.12 scene fixtures with graphs (saved before M1) must render pixel-identical in the preview and within noise in the path tracer.
  • Per node: a BeeScript probe evaluates each node type at fixed points (a matsample() builtin) against reference values computed in Python.
  • Interpreters: the self-test runs random programs through the scalar, SSE and GPU paths and compares outputs.
  • Editor: fakewl drives the editor with the mouse and keyboard alone and reads the graph back through nodeinfo() rather than pixel positions. Pixel checks are kept for colours only.
  • Goldens: the bitmap-font golden 21_palette_split is regenerated when new operators match "spl"; a new golden shows the material editor.
  • Walkthrough: tests/materials.py imports a texture set, builds a parameterised material, makes 3 instances, bakes and exports glTF, then checks the reimport.

Risks

  • Record size. About a dozen files assume 1 KiB records. Mitigation: M1 moves the constants to const.inc and greps for shl 10 and raw offsets; the compatibility fixtures catch any that are missed.
  • GPU interpreter in hand-written SPIR-V. This is the largest single item. It can ship after the release; until then the CPU fallback keeps everything correct.
  • Editor test churn. Tests that click fixed coordinates break when nodes change size. Mitigation: tests read the layout back through a script query (nodeinfo(m, n, "x")) before clicking.
  • Scope. 12 issues. Stage D can follow in v0.13.x if needed; stages A–C already give the Unreal-style editor.
