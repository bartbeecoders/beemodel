Phase 14 · v0.15.0 · Blender files

Open and save .blend files

Blender is where most 3D work lives. This phase makes BeeModel read .blend files itself, with no Blender needed: meshes, UVs, objects, cameras, lights and materials. It also writes them, through the Blender you already have: BeeModel hands it the scene and Blender saves it, so the file is exactly what Blender expects.

BeeModel · Vibecoding/BeeModel-Blend-Plan.html · Companion to the Masterplan · Written 2026-10-16 against v0.14.0

Goals

Open any .blend

Files from Blender 2.80 to 5.2. Compressed files open too (zstd, and gzip from older versions). Meshes with their faces, UVs, smooth or flat shading and material slots; object transforms; cameras and lights; Principled BSDF materials with their image textures, packed or beside the file.

Save for Blender

File › Export › Blender (.blend) writes the scene through Blender, run in the background with its glTF importer, and saves a normal .blend. Without Blender, the menu says so.

Everywhere import is

The File menu, the file browser, drag and drop, file.import_blend for BeeScript and agents. One undo step. Tested in CI without Blender, using files Blender made.

The .blend format

A .blend file is Blender's memory, written block by block. Each block carries the address it had and the number of a struct type. At the end, the SDNA block describes every struct: the names, types and sizes of its fields. A reader that looks fields up by name in the SDNA works across versions. It reads Mesh.totvert by name and never assumes an offset.

VersionsHeaderBlock headerMesh data
2.80–3.3BLENDER-v280 (12 bytes)24 bytes (64-bit)MVert, MPoly, MLoop, MLoopUV arrays
3.4–4.xthe samethe sameNamed CustomData layers: position, .corner_vert, the UV maps, material_index, sharp_face; poly_offset_indices
5.xBLENDER17-01v0502 (17 bytes)32 bytes (64-bit lengths)The same attributes in AttributeStorage

Compressed files start with zstd's magic (Blender 3.0 and later) or gzip's (older). gzip goes through BeeModel's own inflate. zstd goes through the zstd program, which most Linux systems have. Big-endian and 32-bit files (from before 2.80) are refused with a clear message.

Import

  • The scene: the file's current scene. Its objects come from the collections, nested ones included; objects excluded from the view layer are skipped. Each object is placed by its world matrix, turned from Blender's Z up to BeeModel's Y up.
  • Meshes: n-gons are kept. UVs come from the active UV map. Flat faces stay flat. When several objects share a mesh, each gets a copy.
  • Materials: the Principled BSDF's base colour, metallic, roughness, IOR, alpha, emission and transmission. An Image Texture linked to base colour, roughness, metallic or normal (through a Normal Map) becomes a node graph. Images are read from beside the file, or from inside it when packed. A material without nodes uses its viewport colour.
  • Cameras and lights: a camera's lens; point, spot, area and sun lights with their colour and power, as BeeModel lights.
  • Not imported: modifiers (the base mesh comes in), curves, text, Grease Pencil, animation, geometry nodes. The console lists what was skipped.

Export

BeeModel writes the scene as glTF to a private temporary folder, with the material maps baked as glTF export already does. It then runs blender --background --factory-startup with a small script: import that glTF and save the .blend. This runs in the background, and the window keeps drawing. A toast says when it is done, or what Blender reported. The Blender program is set in Preferences › Files (empty: the one on PATH).

One branch with one commit per issue and one pull request for the phase.

Principled BSDF values, Image Texture nodes on the main pins and a normal map. Images come from packed files or from paths relative to the .blend.

Testing

  • tests/fixtures/blend/make.py builds the fixture scenes with Blender itself. It also writes what Blender says about each one (counts, transforms, material values) as JSON next to them. The fixtures are small and committed, so CI needs no Blender.
  • Fixtures: Blender 5.2 plain and zstd, and Blender 4.2 (the 12-byte header and CustomData meshes).
  • The export test runs only when blender is on PATH. It exports a scene, has Blender read the file and report it, and imports the file back.

Budgets & risks

Budgets

  • A 1-million-triangle .blend imports in under 2 s
  • Binary size: about 25 KB more

Risks

  • Blender changes its format. The reader goes by field names, so new fields do no harm. A missing field is reported, not guessed.
  • Pre-3.4 meshes. No Blender that old is at hand, so that path is written against the documented DNA and has no fixture.
  • zstd without the program. The message names zstd. Saving the file uncompressed in Blender also works.
