Phase 13 · v0.14.0 · AI first

Build the whole world by talking to it

BeeModel already speaks MCP: an agent outside the app (Claude Code, Grok, any MCP client) can read the scene, build with every safe operator, script it and look at the viewport. This phase brings the agent inside. The app connects directly to Claude Code, the Grok CLI and OpenRouter. An AI mode lets you describe a world, a model or a change in plain words and watch it being built. Every connection and setting lives in a complete Preferences dialog, which comes first.

Goals

Prompt to world

One prompt (“a misty pine forest around a stone cabin at dusk”) builds terrain, objects, materials, lights, camera and sky. Follow-ups change it (“make the cabin bigger, add smoke”). Each request is one undo step and can be reverted with one click.

Three connections

Claude Code and the Grok CLI run as child processes that drive the app through its own MCP server. OpenRouter (any model) is called over HTTPS, and the app runs the tool loop itself. They all share one tool set and one transcript view.

Settings in one place

A real Preferences dialog (Edit › Preferences, Ctrl+,) with categories, search and defaults. AI connections are set and tested there: paths, models, keys and permissions. Nothing needs a config file edited by hand.

Every connection streams into the same transcript: the model's text, each tool call with its arguments and result (collapsed), and errors. Stop ends the child process or the request. A request that changed the scene can be reverted in one step.

AI mode

The AI Assistant area

Any area can be an AI Assistant: the transcript, a multi-line prompt (Enter sends, Shift+Enter starts a new line), Send and Stop, the connection in use, New Conversation, and Revert for the last request.

The AI workspace

A workspace tab with a large viewport, the AI Assistant beside it and the outliner. Ctrl+Space jumps to the prompt from anywhere.

World building

A system prompt explains the scene conventions, the tools and a way of working: look (scene_summary, viewport_capture), plan, build in batches with script_eval, then look again and fix. Agents can create primitives, geometry-node terrain and scatter, materials with graphs and presets, lights, camera, sky and HDRI.

Safety & secrets

  • Keys are stored in ~/.config/beemodel/secrets (mode 0600), never in the prefs file or a .bee file, and are never logged. The key field is masked. OPENROUTER_API_KEY is used when no key is set.
  • Agents act through the permission tiers they have today. The default is “edit the scene”; file access is opt-in.
  • CLIs only get BeeModel's MCP tools: Claude Code runs with --strict-mcp-config and an allow-list, and Grok in its own working directory.
  • Each request is one undo step and is listed in AI Activity.

Testing

  • No network in CI. The stand-in claude and grok are small Python scripts placed on PATH in the test's HOME. They read their arguments, talk to the app through the MCP bridge as the real ones do, and print the real stream formats.
  • OpenRouter is a localhost HTTP server (the base URL is a setting) that replies with scripted tool calls and checks what it is sent.
  • The UI is tested with fakewl: the Preferences dialog, the AI area and workspace, Stop and Revert.

Budgets & risks

Budgets

  • No frame over 16 ms while an agent runs
  • Stop within 100 ms
  • Binary size: about 60 KB more

Risks

  • CLI output formats change. The parsers ignore unknown events and show raw text as a fallback.
  • TLS in assembly. Avoided: curl does the HTTPS; without curl, OpenRouter is greyed out.
  • Many tools. OpenRouter models get the curated set plus run_operator, not 600 operator tools.
